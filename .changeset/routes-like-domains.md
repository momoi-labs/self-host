Routes are now a hostname, a path and what they do. The Add route dialog picks the domain first, the Zone or any other domain pointed at the Host, then a subdomain or the whole hostname; before, it appended the Zone to anything typed. It then chooses between sending requests to the Application and redirecting them to a path or URL, so sending `admin.example.com` to `/admin` no longer needs a regular expression. A redirect on a new hostname makes it an alias too, so the Host answers it.

Redirects are listed with the routes, on the Routes page and an Application's Routes tab, and Hostname, Alias, Path and Redirect each have an icon. A redirect written as a pattern still opens in the pattern editor. On the Summary, a Domains card lists the hostnames, paths and redirects in sections with their icons and an add action each, drawn as a tree. The card folds, and chips show one kind at a time when there is more than one. The connected databases get the same card, each line with an env chip naming the variable that carries its connection URL, and the diagram fits its card, scrolling only when its content cannot wrap any further. The Application shows the container that receives requests, with its image and port, and the arrow from the domains ends on it; any other containers are listed under it in the same card. That container lists its image, port and start command, or for a Git Application its repository, ref, the file it was built from and the deployed commit with a badge saying whether the ref has moved since. The database page draws the same way: its Applications in a card with their env chips, and the database and volume with their facts.
